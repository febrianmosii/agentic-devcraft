# Invoice download endpoint with IDOR and path traversal

**Skill:** security
**Status:** Illustrative

This scenario was written by a maintainer to show the behaviour the skill is
designed to produce. It is not a recorded transcript.

## Task

> Customers need to download their invoices as PDF from the portal. Add
> `GET /invoices/{id}/download`. The PDFs are already generated into
> `storage/app/invoices/` and the file name is stored in `invoices.file`.
> Make sure it's secure.

Relevant code (`app/Models/Invoice.php` excerpt and routing):

```php
// invoices: id, customer_id, number, file, total, created_at
class Invoice extends Model
{
    protected $fillable = ['customer_id', 'number', 'file', 'total'];
}
```

```php
// routes/web.php
Route::middleware('auth')->group(function () {
    Route::get('/invoices', [InvoiceController::class, 'index']);
    Route::get('/invoices/{id}', [InvoiceController::class, 'show']);
});
```

The `invoices.file` column is populated by a back-office import that accepts
the file name from a CSV uploaded by staff.

## Without the skill

A typical unconstrained response adds the route inside the `auth` group and
this handler:

```php
public function download(int $id)
{
    $invoice = Invoice::findOrFail($id);
    return response()->download(storage_path('app/invoices/' . $invoice->file));
}
```

Report: "Added the secure download endpoint behind authentication. Only
logged-in users can access it. Ran a security review and found no issues."

Two defects ship under the word "secure":

- Any authenticated customer can download any invoice by changing the id
  (`/invoices/1/download`, `/invoices/2/download`, ...). The `auth`
  middleware answers "is someone logged in?", not "may this person read this
  record?".
- `invoice->file` is a staff-supplied string. A CSV row with
  `../../../.env` makes the endpoint serve the application secrets to
  whoever owns that invoice row. The agent treated a database column as
  trusted because it was not a request parameter.

No test was written. "Ran a security review" refers to nothing that
executed.

## With the skill

The agent draws the trust boundary first:

> Inputs: `id` from the URL (customer-controlled); `invoices.file` from a
> staff CSV import (not customer-controlled, but not generated by this
> application either, so not trusted for path construction). Identity: the
> authenticated user, who belongs to one `customer_id`. Resource: one file
> under `storage/app/invoices/`. Sinks: the database lookup and the file
> system read.

It checks how the project already scopes records (`show()` uses a plain
`findOrFail`, which it notes but does not change) and writes:

```php
public function download(Request $request, int $id)
{
    $invoice = Invoice::where('customer_id', $request->user()->customer_id)
        ->findOrFail($id);

    abort_unless(preg_match('/^[A-Za-z0-9_-]+\.pdf$/', $invoice->file), 500);

    $base = realpath(storage_path('app/invoices'));
    $path = realpath($base . DIRECTORY_SEPARATOR . $invoice->file);
    abort_unless($path !== false && str_starts_with($path, $base . DIRECTORY_SEPARATOR), 404);

    return response()->download($path, "invoice-{$invoice->number}.pdf", [
        'Content-Type' => 'application/pdf',
        'X-Content-Type-Options' => 'nosniff',
    ]);
}
```

Tests in `tests/Feature/InvoiceDownloadTest.php`:

- owner downloads own invoice: 200, `Content-Disposition: attachment`.
- authenticated user from another customer requests the same id: 404.
- unauthenticated request: redirect to login.
- invoice row with `file = '../../.env'`: 500 and no file body.

Report:

> Added `GET /invoices/{id}/download` inside the existing `auth` group.
> Controls: lookup scoped by `customer_id` (foreign ids return 404, same as a
> missing invoice); file name validated against `^[A-Za-z0-9_-]+\.pdf$` and
> the resolved path checked to lie inside `storage/app/invoices`; served as
> attachment with `nosniff`.
> Verified: `php artisan test --filter=InvoiceDownload` → 4 passed.
> Not run: `composer audit` (no dependency change); no static scanner is
> configured in this project.
> Outside the request: none.
> Noticed, not changed: `show()` uses `Invoice::findOrFail($id)` with no
> `customer_id` scope, so `/invoices/{id}` has the same IDOR this endpoint
> avoids. The CSV import does not validate `file` on the way in; validating
> there would let the download handler drop its format check.

## Why it matters

Both versions are "behind auth" and both would pass a casual code read. The
unconstrained version leaks every customer's invoices to every other
customer and turns a staff CSV into a file-read primitive, while its report
claims a review that never happened; a human reading that report has no
reason to look closer. The skill version does not add more code than the
problem needs: one scoped query, one format check, one path containment
check, four tests. Its report names each control, quotes the test command and
result, says what was not run, and surfaces the pre-existing IDOR in `show()`
for the human to decide on instead of silently widening the task or silently
ignoring it.
